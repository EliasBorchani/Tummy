## Load-bearing decisions

These are choices that prior sessions made deliberately. **Don't reverse them
without explicit user approval.**

- **100% native UI.** Only design tokens (`core/ui-tokens`) and non-UI code
  are shared via KMP. No Compose Multiplatform runtime on iOS. Don't propose
  CMP unless asked.
- **Koin DSL only, no annotations.** `@Single` / `@Factory` / `@Module` were
  tried and reverted — generated `.module` extensions don't cross module
  boundaries cleanly. All DI is `val xxxModule = module { ... }`.
- **Each bounded context has its own Room `@Database`.** No shared mega-DB.
- **Features never depend on `:data`.** They see `:api` only. `:data` is
  wired at the DI boundary in `umbrella` (iOS) and `composeApp` (Android).
- **No `_app` / `shared` / `core` god-module for cross-context use cases.**
  Either orchestrate in the VM, or identify a missing bounded context.
- **Domain modules don't depend on each other.** Cross-context combine lives
  in features; if it deserves a name, make a new context.
- **Versions pinned in `gradle/libs.versions.toml`.** Don't hardcode in
  `build.gradle.kts`.
- **MVI state is reactive (`combine(...).stateIn(...)`), never mutable.** No
  `updateState` reducer in `BaseViewModel`. See
  [code-style.md#mvi--presentation](./docs/code-style.md#mvi--presentation).
- **Use cases use `suspend fun invoke(...)`, never `operator`.** "Find Usages"
  in Android Studio breaks with `operator`.

## Module quick-reference

```
utilities/          stdlib-level helpers (kotlin-ext, network, presentation)
core/ui-tokens      Kotlin tokens + MOKO strings
domain/<ctx>/api    models + repository interfaces + use cases (pure)
domain/<ctx>/data   Room + impls + Koin module
features/<name>     commonMain-only: VM + State + Intent + Event
umbrella/           iOS framework "TummyShared" + SKIE + Koin init
composeApp/         Android app
iosApp/             Xcode/SwiftUI (XcodeGen-generated)
```

Active bounded contexts: `domain/ingredients/{api,data}`,
`domain/symptoms/{api,data}`. Active features: `features/home`, `features/log`.

## Build commands (most-used)

```
./gradlew :composeApp:assembleDebug --no-configuration-cache                   # Android APK
./gradlew :umbrella:linkDebugFrameworkIosSimulatorArm64 --no-configuration-cache  # iOS framework
./gradlew :umbrella:compileKotlinIosSimulatorArm64 --no-configuration-cache       # iOS code only (no SDK needed)
xcodebuild -project iosApp/iosApp.xcodeproj -scheme iosApp \
           -destination 'generic/platform=iOS Simulator' build                  # full iOS build
```

`--no-configuration-cache` is currently required (Room/MOKO don't fully
support it). Full command list in
[infrastructure.md#build-commands](./docs/infrastructure.md#build-commands).

## Hard rules (don't violate)

- Don't import `Dispatchers.IO` in commonMain — it's iOS-internal.
- Don't use `value class` for any type Swift consumes — SKIE erases it.
- Don't introduce new `:core:*` or `:shared:*` modules.
- Don't edit `iosApp/iosApp.xcodeproj` in Xcode UI — it's generated by
  XcodeGen from `iosApp/project.yml`. Edit the YAML and run `iosApp/regen.sh`.
- Keep `:api` modules pure: no Koin, no Room, no Ktor — just Kotlin and
  `kotlinx.*`.

For *why* each rule exists and full pitfall list, see
[kmp-gotchas.md](./docs/kmp-gotchas.md).
